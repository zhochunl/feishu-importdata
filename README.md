# 飞书多维表格数据导入边栏插件

在浏览器里选择一个 SAS 导出的 zip 数据包，解析其中的 `.sas7bdat`，把每个数据集写入多维表格中同名的数据表。纯前端插件，不需要后端服务，也不需要额外挂 nginx —— 构建产物 `dist/` 由飞书平台自行托管。

## 使用流程

1. 在多维表格「边栏」里添加/打开本插件。
2. **选择数据包**：拖入或点击选择 `.zip`。这一步只读压缩包中央目录，不解密，所以没填密码也不会报错；界面会告知包内 sas7bdat 数量与加密方式。
3. **解压校验**：输入解压密码（SAS 下发的包是 ZipCrypto 加密的），点「校验密码并解析」。插件先只验密码，密码错立刻提示且**保留已选文件**，改完密码直接重试即可，不用重新选包。
4. **写入表格**：校验通过后列出「数据集名 / 行数 / 列数 / 体积」，可搜索、排序、勾选部分数据集，选择写入方式与每批条数，点「开始导入」逐个建表 → 补字段 → 分批写记录；日志区实时显示进度，可随时中止。跑完后按钮变成「重新导入」，日志末尾给出本次总用时。

## 数据映射规则

- 数据表名 = `sas7bdat` 文件头里的表名（如 `LAB`），已存在同名表则复用。
- 字段名 = SAS 变量名；缺失的字段用 `addField` 补齐，已有字段不动。
- 列类型直接采用 `sas7bdat` 自带的变量类型与格式，不再按内容推断：
  - 字符变量 → 文本
  - `DATE` / `DDMMYY` / `YYMMDD` / `MONYY` 等日期格式 → 日期
  - `DATETIME` → 日期时间
  - 其余数值变量 → 数字
- SAS 日期时间以 1960-01-01 为原点，DATE 类存天数、DATETIME 存秒数，按墙上时间转换。
- SAS 缺失值（`.`、`.A`–`.Z`）→ 空值。
- 行数为 0 的空数据集默认**不勾选**：覆盖更新时勾上它会把同名表的旧记录删光却不补新数据。需要只建表结构时手动勾选即可。

## 写入方式

- **追加导入**：保留同名表现有记录，新数据追加在后面。重复导入同一个包会产生重复行。
- **覆盖更新**：同名表先整体删除全部旧记录，再整体写入新数据，字段、视图和仪表盘引用保持不变。执行前有二次确认弹窗；删除不可撤销，中途中止不会自动恢复已删记录。

## 技术栈

- Vite + React 18 + TypeScript + `@lark-base-open/js-sdk`
- `@zip.js/zip.js` 负责浏览器端 ZipCrypto 解密（JSZip 不支持加密包）
- `@irbisadm/statfmt`（ReadStat 的 TypeScript 移植，无原生依赖）读 `.sas7bdat`

## 目录结构

```
importdata/
├── src/
│   ├── App.tsx                 # 边栏界面：选包 → 验密码 → 勾选数据集 / 进度 / 日志
│   ├── main.tsx
│   ├── index.css
│   └── lib/
│       ├── domain.ts           # 列/行类型与取行接口
│       ├── sas7bdat.ts         # SAS 二进制解析：元信息扫描 + 按批重放的行游标

├── devtools/                   # 仅开发用：mock 宿主与探针脚本，不打进 dist
├── index.html
├── package.json
└── vite.config.ts
```

## 本地开发

```bash
npm install
npm run dev        # vite dev server，端口见 vite.config.ts
npm run build      # 产物在 dist/
```

`devtools/mock-host.html` 按 JS SDK 的 postMessage 协议模拟多维表格宿主，可以脱离飞书验证建表、覆盖更新的先删后加、批量降级与中止；它还能把顶层选中的 zip 转交给 iframe 里的插件。

## 飞书插件配置

`dist/` 已随仓库提交，可直接交给飞书平台托管，不必先本地构建。

1. 改了源码后重新 `npm run build`，并把新的 `dist/` 一起提交
2. 在多维表格「扩展程序 → 边栏」创建自定义插件，把构建产物交给飞书平台托管（或填入自己的 HTTPS 地址）
3. 保存后在边栏打开

## 注意事项

- **每批条数**：默认 5000（JS SDK 单次上限）。老宿主可能只接受更小的批量，被拒时（如 `SingleRecordOperationLimitExceeded`，码 10214001）自动沿 5000 → 2000 → 1000 → 500 → 200 降级并保持，日志里会说明降到多少；批量操作是原子的，重切不会写重。撞上写频率/并发限制（1254290 / 1254291）则退避重试，其它错误原样抛出。
- 单表行数受多维表格版本限制（基础版/商业标准版 2000 行，商业专业版 2 万行，商业旗舰版/企业版 5 万行）。`LAB`（约 2 万行）在低版本下会写满溢出。基础版/商业标准版可额外免费领取 1.8 万行权益；超过上限后该数据表无法再新增记录。
- **内存**：`sas7bdat` 的页需要从文件尾部回读，无法只解压前缀，整个数据集的字节必须一次性解出。测试包里 `lab.sas7bdat` 解压后约 469MB，导入时浏览器占用会到 600MB 上下；行本身是按批重放的，不会整体驻留。极宽表请留意浏览器内存。
- 建表幂等，写记录不幂等：要维护数据更新请用「覆盖更新」，不要用追加重复导入。
